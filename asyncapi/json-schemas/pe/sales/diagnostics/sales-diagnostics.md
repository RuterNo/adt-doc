### RuterSalg diagnostics
| Field         | Value                                                                                                             |
|---------------|-------------------------------------------------------------------------------------------------------------------|
| Central Topic | ruter/{operatorId}/{vehicleId}/adt/v3/pe/sales/diagnostics                                                        |
| Schema        | [ sales-diagnostics.json ](json-schemas/pe/sales/diagnostics/sales-diagnostics.json)                              |
| Producer      | Betjent salg                                                                                                      |
| Consumer      | Betjent salg                                                                                                      |
| Service Level | ⛔ Ruter internal API. No restrictions apply. Api may be removed or modified freely by Ruter within major version. | 

Diagnostics message generated by BetjentSalg.

This topic is intended for applications interested in health status for the BetjentSalg application on each vehicle. The health status is intended both as a real time surveillance of health status for each individual vehicle as well as for aggregating data per operator to see larger, more general issues. The topic can also, when enriched by other data, determine whether or not BetjentSalg was used and working on a specific departure.

Below we list possible values for two important enumerations:

**context.trigger**

This value explains what triggered the dispatching of this message.

| Trigger | Description |
|---|---|
| `Startup` | The application process started. Delivery of this message is not guaranteed - it depends on BetjentSalg connecting to the MQTT broker within two minutes, otherwise the message is discarded. |
| `LoginStatusChanged` | The user or system logs the user in or out. |
| `StopPlace` | The vehicle has received information about the next stop on the route. |
| `PrinterStatusChanged` | A printer has connected or disconnected. |
| `NfcStatusChanged` | An NFC reader has connected or disconnected. |
| `InternetConnectionStatusChanged` | The device has connected to or disconnected from the Internet. |
| `MqttBrokerStatusChanged` | The device has connected to or disconnected from the onboard MQTT broker. |

**context.logoutReason**

This value is set when `context.trigger` is `LoginStatusChanged` and the user is logging out. It can be any of the following values:

| LogoutReason | Description |
|---|---|
| `USER_MANUAL_LOGOUT` | The user has actively logged out. |
| `USER_COMPLETED_SETTLEMENT` | The user has actively ended the shift and completed settlement. |
| `INACTIVITY` | The user has been inactive beyond the configured threshold - 6 hours for bus setups, never for merchants. |
| `MISSING_LOGGED_IN_TIME` | System state discrepancy causing logout. |
| `MISSING_USER_ID` | System state discrepancy causing logout. |
| `MISSING_KB_NUMBER` | System state discrepancy related to merchants causing logout. |
| `MQTT_ADT_2_SIGN_OFF` | A signal from the bus (ADT2 protocol `signoff`) indicates the assignment is over and the application should log the user out. |
| `MQTT_ADT_2_NOT_ASSIGNED` | A signal from the bus (ADT2 protocol `di/assignment_attempt`) indicates the assignment is over and the application should log the user out. |
| `MQTT_ADT_3_NOT_ASSIGNED` | A signal from the bus (ADT3 protocol `operational/assignment/attempt`) indicates the assignment is over and the application should log the user out. |
| `OKTA_TOKEN_EXPIRED` | The OAuth2 access token used for authenticating against Tet's backend has expired and the system was unable to renew it. |
| `OKTA_TOKEN_CHECK_FAILED` | A technical error occurred when attempting to check or renew the OAuth2 token. |
| `OKTA_REFRESH_TOKEN_EXPIRED` | The OAuth2 refresh token used for authenticating against Tet's backend has expired and the system was unable to renew it. |
| `SHIFT_ENDED` | The user has actively ended the shift. |
| `DEVICE_SHUTDOWN` | The application reacts to a system shutdown event and logs out the user. |
| `PREFERENCES_RESET` | A user with elevated permissions has opted to reset the application to default settings. |
| `CANCELLED_REGION_PICK` | For setups that are forced through a ship region selector in the login process, this reason is set if the user cancels the dialog. |
| `UNKNOWN_MARKED_LOGOUT` | A default reason that normally should be used when the diagnostics message is dispatched. |
| `UNKNOWN` | A default reason that normally should be used when the diagnostics message is dispatched. |
